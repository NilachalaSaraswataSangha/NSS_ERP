# database/seed/04_admin/

Seeds the initial NSS Admin superuser account. **In progress, uncommitted** on branch
`feature/tier5-authentication-administration`.

Authority: SOL-AUTH-006, Tier 5 decisions.

| File | Seeds |
|---|---|
| `01_admin_bootstrap.sql` | Person `P1` ("NSS Admin"), Sangha Sevi `SS1` (linked to Kendra, `KEN`), `user_account` (status `ACTIVE`, `force_password_change = TRUE`), `password_history`, `user_role` (`NSS_ERP_ADMIN`), `admin_scope` (`NSS-WIDE`) |

**Do not run this file directly with `psql`** — the `user_account.password_hash` column has no
default and the file expects a `%(password_hash)s` bind parameter that only exists at Python
runtime (Argon2 hash generated by the app's own hasher). Run it via:

```bash
python3 scripts/bootstrap_admin.py
# or with a custom password:
python3 scripts/bootstrap_admin.py --password MyCustomPass1
```

Default login: `SS1` (or `P1`) / `NSSAdmin1` — `force_password_change = TRUE`, so the first
login is expected to be followed immediately by `POST /api/v1/auth/change-password`.
**Change this password before using this seed against anything beyond a local dev DB.**

Run as Phase 13 in `database/scripts/02_build.sh`/`.ps1`, after Authentication + Administration
DDL (Phases 10-11) and the `nss_db_writer` grant (Phase 12) — the script connects via
`api/database.py::get_write_pool()`, so it needs `DB_WRITE_USER`/`DB_WRITE_PASSWORD` configured
in `api/.env` first.

Idempotent — every INSERT is guarded by `WHERE NOT EXISTS (...)`, safe to re-run (it will not
duplicate `P1`/`SS1` or overwrite an existing password on a second run).
