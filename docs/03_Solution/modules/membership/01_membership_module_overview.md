# NSS ERP Membership Module Overview

Version: 1.0

Status: DRAFT

---

# 1. Purpose

The Membership Module manages NSS Membership identities, membership lifecycle, membership status, transfers, renewals, attendance-related reviews, and governance eligibility foundations.

The module is built on top of the Person Module.

---

# 2. Core Principle

Person ≠ Member

A Person may exist without Membership.

A Membership must always belong to a Person.

Membership cannot exist independently.

Examples of Persons without Membership:

* Family Members
* Kumari Participants
* Kishor Participants
* Guardians
* Guests
* Historical Persons

---

# 3. Membership Identity

Membership identity is represented by the Sangha Sevi ID.

Example:

```text
SS1
SS2
SS3
```

Rules:

* System Generated
* Globally Unique
* Permanent
* Never Reused
* Never Changed

---

# 3.1 Three-Tier Member Identity Model

Every NSS Member is identified by three distinct identity tiers:

```text
Tier 1: Sangha Sevi ID     — NSS-wide, permanent, never changes
Tier 2: Local Sakha ERP Number  — Sakha-scoped, one active per member
Tier 3: Kendra Number      — via Parichaya Patra document_number
```

## Tier 1 — Sangha Sevi ID

The primary global Membership identity. Assigned once at enrollment and
never changed, even on transfer or renewal.

```text
Format:  SS<sequence>
Example: SS1, SS42, SS1192
```

Stored on: `sangha_sevi.sangha_sevi_id`

## Tier 2 — Local Sakha ERP Number

The Sakha-scoped identifier, also referred to as the **ERP Number**.
The Local Sakha Number and ERP Number are the same identity — these
are two names for a single concept.

```text
Format:  <Sakha Short Code><sequence>
Example: ESS1192 (Ekamra Sakha), CTC42 (Cuttack Sakha)
```

Rules:

* Auto-generated by the system at enrollment or transfer.
* One active Local Sakha ERP Number per member at any time.
* Issued by the member's recognized/base Sakha at enrollment.
* On transfer: old number archived, new Sakha issues next in sequence.
* On return to same Sakha: previously archived number may be reactivated.
* Probationary Members receive a Local Sakha ERP Number from the enrolling Sakha.
* Approved Darshaks (existing members of another Sakha) do NOT receive a second number.

Stored on: `membership_sakha_affiliation.local_sakha_erp_id`

## Tier 3 — Kendra Number

The Kendra-level registration number, carried on the member's
Parichaya Patra as the `document_number`.

```text
Format:  <number>/<financial_year_start>/<financial_year_end>
Example: 345/2026/2027
```

The Kendra Number is assigned when a Regular or Associate Member receives their
Parichaya Patra and serves as the Kendra Sangha's own registration
reference.

Stored on: `parichaya_patra.document_number`

## Identity Summary

| Tier | Name | Scope | Permanent | Changes on Transfer | Storage |
|------|------|-------|-----------|---------------------|---------|
| 1 | Sangha Sevi ID | NSS-wide | Yes | No | `sangha_sevi.sangha_sevi_id` |
| 2 | Local Sakha ERP Number | Sakha | No (archived) | Yes — new number at new Sakha | `membership_sakha_affiliation.local_sakha_erp_id` |
| 3 | Kendra Number | Kendra | Yes (per Parichaya Patra) | No | `parichaya_patra.document_number` |

# 4. One Person One Membership Rule

Frozen Principle:

```text
One Person
    ↓
One Membership
    ↓
One Sangha Sevi ID
```

Rules:

* One Person can have only one Membership.
* One Membership belongs to exactly one Person.
* One Person can have only one Sangha Sevi ID.

# 5. Membership Types

The Membership Module supports the following membership types:

## Probationary Member

Entry-level membership.

Subject to review and evaluation.

In the portal UI, Probationary Member is displayed as **"Darshaka"**
(operational label per MBR-007 — not stored in the database).

---

## Regular Member

Full membership status.

Eligible for governance participation subject to NSS rules.

---

## Associate Member

Special membership category.

Credentials:

* Parichaya Patra — issued upon enrollment (annual renewal required)
* Anumati Patra — NOT applicable (Probationary-only)

Governance eligibility determined by NSS policy.

# 9. Relationship With Person Module

The Membership Module depends on the Person Module.

Relationship:

```text
Person
    ↓
Membership
```

Rules:

* Membership cannot exist without a Person.
* Person records may exist without Membership.
* Membership inherits identity information from Person.

---

# 10. Relationship With Family Module

Family relationships are not maintained by Membership.

Examples:

* Father
* Mother
* Husband
* Wife
* Child

These belong to the Family Module.

---

# 11. Relationship With Governance Module

Membership provides eligibility foundations.

Membership alone does not grant governance authority.

Governance eligibility is controlled by Governance rules.

---

# 12. Relationship With Attendance Module

Attendance affects reviews and membership monitoring.

Attendance alone does not automatically:

* Suspend Membership
* Cancel Membership

Human review is always required.

---

# 13. Membership Transfer

Transfers are supported between Sakhas.

Rules:

* Sangha Sevi ID (Tier 1) remains unchanged.
* Local Sakha ERP Number (Tier 2) may change — old number archived, new Sakha issues next in sequence.
* Kendra Number (Tier 3) remains unchanged.
* Transfer history preserved permanently.
* Effective date follows NSS policy (Dola Purnima).

---

# 14. Membership Renewal

Membership renewal is supported.

Rules:

* Renewal history preserved.
* Sangha Sevi ID remains unchanged.
* Membership identity remains permanent.

---

# 15. Audit Principles

All membership actions must preserve:

* Created By
* Updated By
* Timestamp
* Historical Traceability

Audit history must never be deleted.

---

# 16. Deletion Principles

Physical deletion is prohibited.

Membership history is permanent.

Only status transitions are allowed.
