# Overview

This release is a performance-hardening pass on top of the Tier 4 vertical slice (v0.10.0,
hotfixed through v0.10.3). It does not add tables, endpoints, or tests — it targets a specific
symptom: slow page loads on the Family and Membership verification pages after the Tier 4
FAM-036 majority-rule Sakha computation became a hot path (`_FAMILY_SELECT` in `family.py` and
`_CHILDREN_STATS_SQL` in `organization.py`). All work landed on a single branch,
`performance-optimization`, branched from `main`.

Root cause (full analysis in `docs/03_Solution/architecture/PERFORMANCE_TUNING.md`): sequential
`await` chains in frontend `init()` blocked data loading on a health check; `fetchOrgChildren()`
awaited both a fast children query and a heavy stats query before rendering anything; the
`family_majority` CTE performed full-table scans on three joined tables with only single-column
indexes; a single Uvicorn worker serialized parallel browser requests; and `minconn=1` paid
connection-creation cost on every cold start.

# Features Included

## 1. Composite Partial Indexes (Database)

`database/migrations/add_performance_indexes.sql` — 4 `CREATE INDEX IF NOT EXISTS` composite
partial indexes covering the FAM-036 CTE's join/filter columns:

| Index | Table | Columns | Partial Filter |
|-------|-------|---------|-----------------|
| `idx_family_rel_current_person_family` | `family_relationship` | `(person_pk, family_group_pk)` | `WHERE is_current = TRUE` |
| `idx_sangha_sevi_active_person` | `sangha_sevi` | `(person_pk, sangha_sevi_pk)` | `WHERE is_active = TRUE` |
| `idx_mem_sakha_aff_active_covering` | `membership_sakha_affiliation` | `(sangha_sevi_pk, organization_pk)` | `WHERE effective_to IS NULL` |
| `idx_organization_parent_active` | `organization` | `(parent_organization_pk)` | `WHERE is_active = TRUE` |

Wired into `database/scripts/02_build.sh`, `02_build.ps1`, and `render_build.sh` as a new
"Phase 8b" build step, run automatically on every build/deploy.

**Known inconsistency, flagged not fixed:** placing a schema-affecting file in
`database/migrations/` and auto-running it from the build scripts contradicts that folder's own
documented convention (reserved for one-off *data-fix* scripts, never schema changes, never
wired into the build). See `database/migrations/README.md` — left for a future decision (move
under `database/ddl/`, or formally amend the convention).

## 2. Server Concurrency (API)

`render.yaml` start command gains `--workers 2` (Render free tier, 512 MB RAM — 2 workers ≈
160 MB, leaving headroom for query buffers). `api/database.py`'s connection pool `minconn` goes
1 → 2, pre-warming enough connections that a 2-worker deployment has no cold-start latency on
first request.

## 3. Non-Blocking Frontend Fetches

`frontend/assets/js/family.js` and `frontend/assets/js/membership.js`: `init()`'s health check
is now fire-and-forget (not awaited) — it only updates a status badge and no longer blocks data
loading. `family.js`'s `fetchOrgChildren()` no longer awaits the heavy `/children-stats` query
before rendering — it renders the fast children list immediately, then a new
`_fetchOrgChildrenStats()` method fetches stats in the background and fills in count badges
once they arrive (non-fatal on failure). Cache-bust bumps: `family.js?v=24`,
`membership.js?v=4.0`.

## 4. Documentation

New `docs/03_Solution/architecture/PERFORMANCE_TUNING.md` (root-cause analysis, scaling
guidance for workers/pool size, cache-busting convention). `DEPLOYMENT_PROCEDURE.md` and
`TECH_STACK_DECISIONS.md` updated to match. Reconciliation pass across `CLAUDE.md`, root
`README.md`, `docs/PROJECT_DOCUMENTATION.md`, `api/README.md`, `database/README.md`,
`database/scripts/README.md`, `database/migrations/README.md`, `tests/README.md`,
`frontend/README.md`, `docs/03_Solution/ui/README.md`, and the API/UI code-explanation docs —
correcting drift accumulated since v0.10.0 (stale Tier 2 endpoint count, stale test counts,
stale Family table count, and the undocumented v0.10.1–v0.10.3 hotfix tags), on top of
documenting this release's own changes.
