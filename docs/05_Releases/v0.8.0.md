# Overview

This release completes the Tier 2 Organization vertical slice on top of the 3-table database
implemented in v0.6.0: a 6-endpoint read-only API (including a self-referencing hierarchy tree
via a recursive CTE), a 3-tab verification UI, and 51 new integration tests. Alongside the API
work, the `organization` table gained 8 contact/online-presence columns (phone, mobile, email,
website, YouTube — both NSS-wide and org-specific variants), exposed through the same endpoints.
This release also finishes reorganizing the code-explanation documentation set: it moves out
from under `architecture/` into its own top-level `docs/03_Solution/code_explanations/` folder,
and consolidates all API contracts (Bootstrap, Foundation, Organization) into a new
`docs/03_Solution/api/` folder.

**139 tests total** now cover the codebase: 21 (Tier 0 Bootstrap) + 59 (Tier 1 Foundation) + 51
(Tier 2 Organization) + 8 (security middleware).

# Features Included

## 1. FastAPI Tier 2 Organization API (6 read-only endpoints)

Under `api/routers/organization.py`, across all 3 Organization tables:

| Endpoint | Purpose |
|----------|---------|
| `GET /api/v1/organization/types` | 8 frozen organization types |
| `GET /api/v1/organization/statuses` | 6 lifecycle statuses |
| `GET /api/v1/organization/organizations` | List, optional `type_code`/`status_code` filters |
| `GET /api/v1/organization/organizations/{organization_pk}` | Single organization detail |
| `GET /api/v1/organization/organizations/{organization_pk}/children` | Direct children of an org |
| `GET /api/v1/organization/hierarchy` | Full self-referencing tree via a `WITH RECURSIVE` CTE |

* Every list/detail endpoint JOINs type/status masters, the self-referencing parent, and the
  full geography chain (district/state/country/city_village/postal_code).
* 4 new Pydantic response models (`api/schemas/organization.py`).
* Full contract: `docs/03_Solution/api/ORGANIZATION_API_CONTRACT.md`.

## 2. Organization Contact & Online-Presence Fields

`nss.organization` gained 8 new columns: `phone_number`, `mobile_number` (both nullable),
`email`, `website_url`, `youtube_channel_url` (NSS-wide, `NOT NULL` with sane defaults —
`info@nsspuri.org`, `https://www.nsspuri.org`, the NSS YouTube channel), and `org_email`,
`org_website_url`, `org_youtube_channel_url` (org-specific, nullable). Exposed on
`OrganizationResponse` and in the Organizations tab's detail panel (Contact + Online Presence
sections).

## 3. Tier 2 Organization Verification UI

Under `frontend/organization.html` + `frontend/assets/js/organization.js`:

* 3-tab layout: Reference Data (Types + Statuses side by side), Organizations (filterable list +
  detail panel with Contact/Online-Presence/Address/Geographic sections + a Children sub-table),
  Hierarchy (flat CTE result rendered as an indented tree client-side)
* Served at `GET /organization`, mirroring the existing `/foundation` pattern
* Nav bar now links all three verification UIs (`/`, `/foundation`, `/organization`)

## 4. Test Suite Growth (64 → 139 tests)

* `tests/test_organization.py` — 51 tests, 7 classes: types/statuses reference data, organization
  list/detail/filtering/contact-field assertions, children, hierarchy, UI structure, and security
  headers.
* `tests/test_bootstrap.py` and `tests/test_foundation.py` each gained a UI-structure test class
  (`TestBootstrapUI`, additions to `TestFoundationUI`) for consistency across all three
  verification pages.
* Security audit extended: `TIER2_SECURITY_AUDIT.md` — 15 checks passed, 0 fixes required, 4
  advisory items (pagination, CTE depth, filter logging, helper duplication).

## 5. Documentation Reorganized Further: `code_explanations/` and API Contracts Out of `architecture/`

* `docs/03_Solution/architecture/code_explanations/` → `docs/03_Solution/code_explanations/`
  (one level up — it documents implementation, not architecture). All 5 per-layer docs
  (API/Database/UI/Security/Testing) updated with full Tier 2 Organization coverage.
* API contracts consolidated into a new `docs/03_Solution/api/` folder:
  `BOOTSTRAP_API_CONTRACT.md` (new), `FOUNDATION_API_CONTRACT.md` (moved, unchanged),
  `ORGANIZATION_API_CONTRACT.md` (new).
* `api/README.md`, `frontend/README.md`, `tests/README.md`, and the Organization/Foundation
  module design READMEs updated with full Tier 2 sections.
* Corrected several stale test counts found during reconciliation (the Tier 2 feature commit's
  own claim of "136 total tests" was itself off — the verified total is 139).

# Frozen Decisions (New in v0.8.0)

* **Organization's contact/online-presence fields default to NSS-wide values** — `email`,
  `website_url`, and `youtube_channel_url` are `NOT NULL` with an NSS-wide default, while the
  `org_*` variants are nullable and org-specific; a consuming org only needs to override the
  ones that differ from NSS-wide contact info.
* **Code-explanation docs live at the `docs/03_Solution/` top level, not under `architecture/`**
  — they document implementation across every tier, which isn't an "architecture" concern per
  se; this also means future tiers extend the same 5 per-layer files rather than adding new ones.
* **API contracts are consolidated under `docs/03_Solution/api/`, one file per tier** — going
  forward, a new tier's contract doc joins this folder rather than living under `architecture/`.
