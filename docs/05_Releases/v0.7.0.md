# Overview

This release completes the Tier 1 Foundation vertical slice on top of the 12-table database
implemented in v0.6.0: a 17-endpoint read-only API, a 4-tab verification UI, and 47 new
integration tests. Alongside it, a cross-tier security-hardening pass adds HTTP security
headers, opt-in CORS, rate limiting, and CDN Subresource Integrity pinning to both Tier 0 and
Tier 1 — covered by 8 additional tests and two updated security audit reports. The
code-explanation documentation set was also reorganized from per-tier walkthroughs into
per-layer ones (API/Database/UI/Security/Testing), so it scales cleanly as new tiers and layers
(e.g. a future mobile client) are added.

**64 tests total** now cover the codebase: 9 (Tier 0 Bootstrap) + 47 (Tier 1 Foundation) + 8
(security middleware).

# Features Included

## 1. FastAPI Tier 1 Foundation API (17 read-only endpoints)

Under `api/routers/foundation.py`, across 11 of the 12 Foundation tables:

| Group | Endpoints |
|-------|-----------|
| Master data | `/categories`, `/categories/{pk}`, `/master-data` (filter by `category_code`/`category_pk`), `/master-data/{pk}` |
| System config | `/settings`, `/settings/{setting_key}`, `/sequences` (excludes `current_value`) |
| Geographic | `/countries`, `/countries/{pk}`, `/states`, `/states/{pk}`, `/districts`, `/districts/{pk}`, `/cities`, `/postal-codes`, `/postal-code-mappings` |
| Runtime | `/documents` |

* `nss.field_change_log` is deliberately **not exposed** — deferred to Tier 5 (needs auth);
  guarded by a dedicated regression test.
* New Tier 1 conventions: query-param filtering instead of nested paths, hierarchical
  drill-down (Country → State → District → City/Village), no pagination.
* 11 new Pydantic response models (`api/schemas/foundation.py`), audit columns and
  `current_value` excluded by design.
* Full contract: `docs/03_Solution/architecture/FOUNDATION_API_CONTRACT.md` (v1.1).

## 2. Tier 1 Foundation Verification UI

Under `frontend/foundation.html` + `frontend/assets/js/foundation.js`:

* 4-tab layout: Master Data, System Config, Geographic drill-down, Runtime Tables
* Lazy per-tab data loading; toggle-deselect on country/state/district selection
* Shares the Tier 0 System Status card and CDN stack; nav bar links between `/` and `/foundation`

## 3. Security-Hardening Middleware (cross-tier: Tier 0 + Tier 1)

Under `api/middleware.py` and `api/main.py`:

* **Security headers** on every response — `X-Content-Type-Options: nosniff`,
  `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`,
  `Permissions-Policy: camera=(), microphone=(), geolocation=()`; `Cache-Control: no-store`
  scoped to `/api/*` only.
* **Rate limiting** (`slowapi`) — default `60/minute` per client IP, configurable via
  `RATE_LIMIT`; global (`SlowAPIMiddleware`).
* **CORS** (`fastapi.middleware.cors.CORSMiddleware`) — opt-in only, via `CORS_ORIGINS`; no
  middleware registered at all when unset, so no CORS headers ever appear by default.
* **`DISABLE_DOCS`** toggle — hides `/docs`, `/redoc`, `/openapi.json` in production.
* **CDN Subresource Integrity** — DaisyUI pinned to `4.12.14` and Alpine.js to `3.14.8`, both
  with `integrity`/`crossorigin` SRI attributes, on both `index.html` and `foundation.html`.
  Tailwind's Play CDN remains unpinned (browser-side JIT compiler — SRI does not apply).

## 4. Test Suite Growth (9 → 64 tests)

* `tests/test_foundation.py` — 47 tests, 13 classes, covering every Tier 1 endpoint plus two
  contract-enforcement regressions (`current_value` never exposed, `/change-log` 404s/405s).
* `tests/test_security.py` — 8 tests, 3 classes, covering security headers, `Cache-Control`
  scoping, rate-limit 429, and CORS behavior. Caught a real bug during development:
  `SlowAPIMiddleware` had been configured but never registered, so rate limiting was silently
  inert until the test caught it.
* `pytest`/`httpx` now pinned in `requirements.txt` (previously undeclared, even though
  `TestClient` requires `httpx` at import time).

## 5. Security Audit Reports Updated

* `TIER0_SECURITY_AUDIT.md` bumped to v1.1 — 10 checks passed, 1 fix applied, 6 advisory items
  (4 resolved, 1 partial — CDN SRI, 1 N/A — `psycopg2-binary`).
* `TIER1_SECURITY_AUDIT.md` bumped to v1.1 — 9 checks passed, 6 advisory items (3 resolved, 1
  partial, 1 advisory — pagination, 1 N/A).
* No blocking vulnerabilities found in either audit.

## 6. Documentation Reorganized: Per-Tier → Per-Layer Code Explanations

Retired `TIER0_VERTICAL_SLICE.md`, `TIER1_FOUNDATION.md`, and `SECURITY_HARDENING.md` (which
interleaved the same files' narration across multiple tier-scoped documents) and replaced them
with five per-layer documents under `docs/03_Solution/architecture/code_explanations/`, each
giving every source file in that layer its own "Requirement + Line-by-line" section with real
fenced code blocks:

* `API_CODE_EXPLANATIONS.md` — every `api/` file except `middleware.py`
* `DATABASE_CODE_EXPLANATIONS.md` — all 41 DDL/seed/script files under `database/`, full
  column-by-column detail
* `UI_CODE_EXPLANATIONS.md` — every `frontend/` source file
* `SECURITY_CODE_EXPLANATIONS.md` — `api/middleware.py` in full, plus the security-relevant
  slices of `api/config.py`/`api/main.py`, plus CDN SRI pinning
* `TESTING_CODE_EXPLANATIONS.md` — all 64 tests under `tests/`

This structure scales cleanly as new layers are added in the future (e.g. a Flutter mobile
client). `tests/README.md` was also added as the test inventory `docs/04_Testing/README.md`
already pointed to.

# Frozen Decisions (New in v0.7.0)

* **Security middleware is cross-tier, not per-tier** — one shared stack (`api/middleware.py`)
  protects every route, Tier 0 and Tier 1 alike.
* **CORS defaults to fully off** — no wildcard origin is ever supported; either an explicit
  allow-list or no CORS middleware at all.
* **Rate limiting is global, not per-route** — a single default limit applies everywhere until
  a future tier needs a different one.
* **Code-explanation docs are organized per-layer, not per-tier** — going forward, a new layer
  (e.g. mobile) gets its own `<LAYER>_CODE_EXPLANATIONS.md` rather than a new per-tier doc.

# Notes

The Foundation module is now the first Solution-layer module with a complete DB → API → UI
vertical slice, verified end to end by its own test suite and a dedicated security audit. The
security-hardening pass was deliberately scoped cross-tier rather than repeated per-tier, since
headers/CORS/rate-limiting are transport-layer concerns that apply identically regardless of
which router or table is being served.
