# Overview

Patch release fixing two deploy-correctness gaps discovered while verifying that Tier 4
(v0.10.0) could actually be rolled out to the Neon.dev production database:

1. `database/scripts/02_build.sh`'s Phase 6/8 never created or seeded `nss.family_link` — the
   Family Graph feature's edge table (added under `database/ddl/04_family/`/`seed/04_family/`
   during Tier 4, but never wired into the build script's execution list).
2. `render_build.sh` (the Render/Neon deploy script) stopped after Phase 5 (Person) entirely —
   no Family or Membership DDL, seed, or grant step at all — and its binary "skip if
   `role_master` already exists" gate meant an already-bootstrapped database would never pick
   up any newly added phases on redeploy.

Commit: `6b31500` — `fix(database): wire family_link into build scripts, extend render_build.sh
through Tier 4`.

---

# Fixes

## 1. `database/scripts/02_build.sh` — family_link wiring

Phase 6 now creates `nss.family_link` (`ddl/04_family/05_family_link.sql`); Phase 8 now seeds it
(`seed/04_family/02_tier4_verification_family_links.sql`). Both existed on disk since Tier 4
merged but were never invoked by the build script.

## 2. `render_build.sh` — full Phase 0-9 parity

Previously stopped after Phase 5 (Person) — no Family, Membership, Tier 4 verification seed, or
grant step ran on Render/Neon at all. Now runs the full Phase 0-9 sequence on every deploy,
adopting the same idempotent per-statement skip-on-"already exists" logic `02_build.sh` already
used (rather than a hard-fail `run_sql`), and drops the binary all-or-nothing bootstrap gate — so
a redeploy against an already-bootstrapped Neon database safely picks up any newly added phases
without dropping or recreating anything.
