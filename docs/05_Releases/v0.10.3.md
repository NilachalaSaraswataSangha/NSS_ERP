# Overview

Patch release fixing the actual root cause behind a production bug on the Neon.dev database:
`nss.master_data` was missing the `applicable_modules` column (added to its DDL after the
database had already been bootstrapped), and several multi-`INSERT` seed files would silently
abort partway through on the first pre-existing row (`psql -v ON_ERROR_STOP=1`), leaving newer
categories/columns unseeded with no error surfaced — most visibly, missing newer `STATUS`
values and the entire `RELATIONSHIP_TYPE` category.

The previous idempotency approach (`02_build.sh`/`render_build.sh` grepping shell output for
"already exists") only detects a *failed statement* — it does nothing for a schema that has
since drifted, such as a column added to a `CREATE TABLE` after some databases already had that
table. This release replaces shell-level detection with genuine PostgreSQL-level idempotency.

Merge commit: `6677b95` — `merge: hotfix/master-data-applicable-modules-column into main`.

# Fixes

## 1. Idempotent DDL

Every `CREATE TABLE`/`CREATE INDEX`/`CREATE UNIQUE INDEX` across 23 DDL files in
`database/ddl/` (Bootstrap, Foundation, Organization, Person, Family, Membership) now uses
`IF NOT EXISTS`. `nss.master_data` additionally gets an explicit
`ALTER TABLE ... ADD COLUMN IF NOT EXISTS applicable_modules` safety net.

## 2. Idempotent Seed Data

Every `INSERT` across the affected seed files (`00_bootstrap`, `01_foundation`,
`02_organization`, `03_person`, `04_family`, `05_membership`, plus the standalone
`99_extended_test_data.sql`/`99_fix_memberships.sql`) is now an upsert
(`ON CONFLICT ... DO UPDATE`, matched against each table's real `UNIQUE` constraint — including
partial unique indexes for "current row" tables). Genuinely append-only history/event tables
with no natural key are deliberately left as plain `INSERT`, with a comment explaining why.

## Impact

Any database, regardless of how stale, now self-heals to the current schema and seed values on
its next rebuild — a fresh `02_build.sh`/`render_build.sh` run against an already-bootstrapped,
drifted database will add missing columns and upsert missing/changed rows instead of silently
skipping them.

# Database Objects Summary

No new tables. Schema change: `nss.master_data` gains `applicable_modules` (via
`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`, applied idempotently to already-bootstrapped
databases). Table count unchanged at 35.

52 files touched in total: 23 DDL files (idempotent `CREATE`), 18 seed files (idempotent
upsert), plus the 2 standalone `99_*.sql` scripts and DDL for `anumati_patra`/
`anumati_patra_history`.

# Release Summary

Completed:

* Every `CREATE TABLE`/`CREATE INDEX`/`CREATE UNIQUE INDEX` in `database/ddl/` now idempotent
  via `IF NOT EXISTS`
* `nss.master_data.applicable_modules` column added via idempotent `ALTER TABLE`
* Every seed `INSERT` converted to an idempotent upsert (`ON CONFLICT ... DO UPDATE`)
* Root cause fixed: a stale/drifted database now self-heals on rebuild instead of silently
  skipping newer schema/seed changes

Known gaps carried forward (not blocking this release):

* All Deferred Items open as of v0.10.0-v0.10.2 remain open — this release is a database
  idempotency fix only, no application-layer changes
* No automated test asserts idempotency itself (i.e. running `02_build.sh` twice against the
  same database and diffing the result) — verified manually for this release
